# segmented-append-log-go

可崩溃恢复的分段式追加日志存储组件（包名 `seglog`），作为上层数据库或消息系统的本地持久化底座。仅依赖 Go 标准库。

## 存储格式与版本兼容

每条记录/每个块的二进制格式（格式版本 **v1**）：

```
[magic uint32 LE][length uint32 LE][crc32 uint32 LE][payload ...]
```

- `magic` 标识记录类型，用于定位记录边界与版本识别：
  - `0x53514C31`（"SQL1"）：完整记录（v1，单块即可容纳）；
  - `0x53514C46`（"SQLF"）：跨段记录的**首块**（v2）；
  - `0x53514C4D`（"SQLM"）：跨段记录的**中间块**（v2）；
  - `0x53514C4C`（"SQLL"）：跨段记录的**末块**（v2）。
- `length` 为该块 payload 字节数。
- `crc32`（IEEE）覆盖 `length` 字段与 `payload`，用于检测半写与位翻转。

**兼容规则**：未知 magic 一律视为非法数据（`bad-magic`），不会被当作任何旧版本格式解析。v1 写入的数据文件（全部使用 "SQL1"）可被直接读取；单块记录仍写 "SQL1"，不产生格式迁移。

## 段组织

数据目录下按段存储，段文件名为 `%020d.%06d.seg`：

- 第一段数字是**逻辑 base** = 此段之前已开始的记录数（首段文件名携带已被回收的前缀长度，恢复时据此确定起始逻辑偏移）；
- 第二段数字是**序号**：一条大记录跨 3 段以上时会出现连续的"纯续块段"，它们逻辑 base 相同，用序号区分（无序号的旧格式 `%020d.seg` 按序号 0 兼容解析）。

段写满 `MaxSegmentBytes` 后滚动新段。段文件句柄不常驻：所有读写经由有上限的句柄池（`MaxOpenFiles`，LRU 淘汰），长时间运行句柄数不越界。

## 跨段记录

当一条记录放不进当前段剩余空间（或本身就大于单段）时，被拆成连续多个块依次写入后续分段：

- 记录在**首块**处分配逻辑偏移；读方按偏移 `Read` 时自动跨段拼装，仍作为一条完整记录返回。
- 剩余空间连一个块头都放不下时直接滚动新段（段尾留空，文件中不存在填充字节）。
- 写到一半崩溃：已写入的块本身可能完整可解码，但记录未完结。恢复时整体回退到首块处截断，归类为 **`partial-record`**（`CorruptPartialRecord`），与 `torn-tail`（块本身没写完）、`checksum-mismatch` 等其它损坏可区分。半截记录永远不会作为完整记录返回。
- 首段开头出现的孤儿续块视为"首块在已被回收的前段中"，恢复时跳过，不算损坏。

## 恢复语义

`Open` 时逐段顺序解码记录/块，推导确定的可用范围：

- 扫描在遇到第一条无法完整解码的记录或未完结的跨段记录时停止，该位置即**有效数据终点**；其后所有字节（含后续段）被截断/删除，恢复结论与正常关闭后再打开完全一致。
- 崩溃可能留下"刚滚动出、尚未写入"的空尾段，恢复时识别并清除。
- 损坏原因可区分（`RecoveryInfo.Corrupt` 与 `*CorruptError.Kind`）：
  - `torn-tail`：尾部残余不完整数据（块本身写了一半），安全截断；
  - `partial-record`：跨段记录只写入一部分块（写到一半的残余），整体回退到首块截断；
  - `bad-magic`：魔数不匹配；
  - `bad-length`：长度字段非法；
  - `checksum-mismatch`：CRC 校验失败。
- 恢复后 `NextOffset == ValidEnd`，追加从该位置继续，偏移连续不跳号。

## 并发与背压

- `Append` 在互斥锁下分配逻辑偏移，多写并发时偏移全局唯一、连续不跳号；读方只能看到完整且已提交的记录。
- 读并发通过槽位（`MaxReaders`）限流，超限立即返回 `ErrTooManyReaders` 而非阻塞。
- 未刷盘字节达到 `MaxInflightBytes` 时，`Append` 返回 `ErrBackpressure`；调用 `Sync` 后恢复可写。不会静默丢弃，也不会阻塞整个进程。
- 单条记录超过 `MaxRecordBytes` 返回 `ErrRecordTooLarge`。

## 容量天花板

三项资源上限都可配置，长时间运行不无限增长：

- `MaxTotalBytes`：数据目录总字节数；
- `MaxSegments`：段数量；
- `MaxOpenFiles`：同时打开的段文件句柄数（LRU 淘汰，超界自动关闭最久未用句柄）。

写入前预演本次追加所需的字节数与段数；触顶时**先按消费进度自动回收**确定无人再要的旧段腾地方；仍腾不出时，`Append` 立即返回 **`ErrNoCapacity`**——与 `ErrBackpressure`（在途字节背压）等其它结果可区分，不静默丢数据、不卡住进程。

## 回收与消费进度

读取方通过 `RegisterReader(name)` 注册，用 `Commit(off)` 显式上报消费进度（`off` 为下一条待读偏移，即 `< off` 的记录均已消费），不再使用时 `Close()` 注销。

- **回收界 = 所有已注册读取方的最小消费进度**。手动 `Reclaim(before)` 与容量触顶时的自动回收都被钳制到该界：任何读取方还没越过的数据不会被回收，慢消费者会钉住它还没读到的数据。
- 新注册、尚未提交过进度的读取方按进度 0 处理（钉住全部数据）。
- 没有任何已注册读取方时：手动 `Reclaim` 不受钳制（调用方自行负责），容量触顶时**不做**自动回收（无法确定谁还需要数据），直接返回 `ErrNoCapacity`。
- 读取已回收位置返回 `ErrOffsetReclaimed`，读取从未写过的位置返回 `ErrOffsetOutOfRange`，两者可区分。

## 可配置项（`Config`）

| 字段 | 含义 | 默认值 |
|---|---|---|
| `Dir` | 数据目录 | 必填 |
| `MaxSegmentBytes` | 单段最大字节数，超过滚动新段（最小 64） | 64 MiB |
| `MaxRecordBytes` | 单条记录最大字节数 | 4 MiB |
| `MaxInflightBytes` | 在途未刷盘字节上限（背压阈值） | 16 MiB |
| `MaxReaders` | 并发读槽位上限 | 128 |
| `SyncOnAppend` | 每次追加后立即刷盘 | false |
| `MaxTotalBytes` | 数据目录总字节上限 | 1 GiB |
| `MaxSegments` | 段数量上限 | 1024 |
| `MaxOpenFiles` | 同时打开的段文件句柄上限 | 64 |

## 本地验证

```bash
go build ./...
go vet ./...
go test ./seglog/ -v        # 功能与崩溃恢复测试，日志打印恢复位置与错误归类
go test ./seglog/ -race     # 并发竞态检测
```

测试覆盖：

- 写入各阶段异常终止：块头写一半、负载写一半、跨段记录首块/中间块/末块各阶段中断、空尾段、坏魔数、坏长度、坏 CRC；验证恢复出的可用范围与可继续写入位置跟正常关闭一致，日志打印恢复位置（`next`/`validEnd`/`truncated`）与每类结果的归类（`torn-tail`/`partial-record`/...）。
- 跨段记录：大于单段的记录拆块写入、跨段拼装读回、重启后仍完整。
- 容量上限：总字节数与段数触顶时先按消费进度自动回收，回收不出空间返回 `ErrNoCapacity`（与 `ErrBackpressure` 区分）；句柄池 LRU 不越 `MaxOpenFiles`。
- 回收与消费进度：慢消费者钉住回收界、已回收位置与从未写过位置可区分、注销后不再钉住。
- 正常关闭与异常终止恢复结论一致性、段滚动、多写多读并发、写/读/提交/回收混合并发（race 检测）。
